# 🚀 슈팅 게임

## 1. 프로젝트 개요

- **개발 기간 :** 2026.03 ~2026.04
- **1인 프로젝트**
- **한줄 소개 :** **Java Swing**과 **TCP Socket** 프로그래밍을 활용하여 서버-클라이언트 간 실시간 데이터 동기화를 구현한 2인용 협동 슈팅 게임입니다.
- **핵심 기능** 
① 실시간 위치 동기화.
② 서버 중심의 데이터 관리. 
③ 멀티스레딩을 이용한 화면 끊김 최적화.

## 2. 테스트 실행 및 방법

### 2-1. 실행 방법

1. **Server 실행 :** `MyFrameServer.java` 를 실행 한 후 ‘게임 시작’ 버튼 클릭 (클라이언트 접속 대기).
2. **Client 실행 :** 코드 실행 전, 서버 컴퓨터의 IP주소를 확인하여 (`GameStartPanelClient.java`)의 `Socket` 주소를 서버 컴퓨터의 **IP 주소(포트번호)**로 수정한 후, `MyFrameClient.java` 를 실행하여 ‘게임 시작’ 버튼 클릭.

```sql
clientSocket = new Socket("서버의_IP_주소", 8000);
```

## 3. 주요 기능

- **실시간 멀티플레이 동기화(2명):** 서버와 클라이언트 간에 플레이어/에너미 좌표, 미사일 위치, HP 상태 등을 실시간 동기화합니다.
- **서버 중심 데이터 제어**: 서버에서 적 유닛 생성, 점수 계산 등을 통합 관리하여 데이터 불일치를 방지합니다.
- **독립적 렌더링 시스템:** 네트워크 수신 주기와 별개로 클라이언트와 서버가 스스로 화면을 그리는 전용 타이머를 탑재하여 부드러운 움직임을 유지합니다.
- **데이터 수신/화면 갱신 분리**: 네트워크 수신 주기와 상관없이 전용타이머(`Swing Timer`)가 독립적으로 화면을 그려 부드러운 움직임을 제공합니다.
- **견고한 예외처리:** 서버/클라이언트 중 한쪽이 이탈 등 돌발 상황 시, 에러로 멈추는 것이 아니라 알림창, 함께 시작하기 위해 기다리는 화면 등 안전하게 종료되도록 설계했습니다.

## 6.  트러블 슈팅 (Trouble Shooting)

**① 대용량 객체 전송 방식 개선( `ObjectOutputStream` → `DataOutputStream` )**

- **문제:** 서버에서 관리하는 게임 객체 전체를 `ObjectOutputStream` 을 통해 통째로 전송하려 했으나, 데이터 크기가 너무 커 전송 지연이 발생하고, **데이터 처리가 불안정 현상** 발생.
- **해결**: 전송 방식을 **`DataOutputStream`**(Primitive Type) 데이터 전송으로 변경. 객체 전체가 아닌 좌표, 상태값 등 핵심 데이터만 추출하여 작게 쪼개 전송하는 방식으로 최적화.
- **결과**: 네트워크 부하를 줄이고 데이터 수신 속도를 대폭 개선함.

**② 서버 중심 로직 통합** 

- **문제:** 초기 설계 시 클라이언트에서도 충돌 판정 및 점수 로직을 실행하였으나, 두 환경의 연산 속도 차이로 인해 **데이터 불일치**가 발생.
- **해결:** 모든 핵심 로직(충돌 판정, 체력관리, 아이템/적 생성 등)을 **서버에서만 수행**하도록, 아키텍쳐를 개선. 클라이언트는 ‘사용자 입력 전송’과 ‘서버 데이터 렌더링’ 역할만 수행하는 구조로 단순화함.
- **결과:** 클라이언트의 연산 부담이 줄여 **실행 속도를 약 5배 이상 향상**하였으며, 서버가 모든 판정의 권한을 가짐으로써 **데이터 정합성**을 확보함.

## 7. 선정이유

**자바 언어의 심화 학습**과 더불어, 네트워크 프로토콜의 기초인 **소켓 프로그래밍**을 실제 서비스에 녹여보고자 본 프로젝트를 기획했습니다. 실시간 데이터 동기화가 필수적인 2D 네트워크 슈팅 게임을 구현함으로써, 멀티스레딩 환경에서의 자원 관리와 서버-클라이언트 간의 **효율적인 데이터 통신 메커니즘**을 깊이 있게 학습하고자 했습니다.

## 8. 회고 (느낀점/성장점)

단순히 Java 언어를 익히는 것을 넘어, **객체지향언어의 적용**과 **실시간 네트워크 아키텍처**를 깊이 있게 탐구한 과정이었습니다. 초기에는 모호했던 업캐스팅와 인스턴스변수 및 함수 등의 객체지향의 핵심 개념들을 코드로 직접 구현하고 직면하면서 기본기를 재정립할 수 있었습니다. 특히, 서버-클라이언트 간의 실시간 데이터 동기화 매커니즘을 직접 설계하고, 성능을 위해 시스템 아키텍쳐를 보다 효율적인 구조로 개선하는 과정에서 수많은 시행착오를 겪었습니다. 이를 통해 작은 로직 차이가 사용자에게 얼마나 큰 영향을 미치는지 체감했습니다.
